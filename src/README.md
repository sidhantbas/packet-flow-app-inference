# Source code catalogue

> **Generated file** (`.venv/bin/python src/build_experiments_index.py`). All code stays in this one folder on purpose:
> runners are run as `.venv/bin/python src/<file>.py` from the repository root and import the library and each other
> by module name, and every run folder in `results/` records these paths.

## Library (production and evaluation)

| File | Role |
|---|---|
| [`cv.py`](cv.py) | Data loading (`load_task`), feature functions (`TASK_FEATURES`) and repeated stratified CV (`evaluate`); each task reads only its own folder |
| [`models.py`](models.py) | Every model and expert; the production registry `TASK_MODELS` |
| [`runlog.py`](runlog.py) | `record_run`: immutable, hashed run folders in `results/`, paired comparison with the champion, rule v2 verdict |
| [`runs.py`](runs.py) | Command line for runs: `status`, `verify`, `compare`, `champion`, `rejudge` |
| [`make_submission.py`](make_submission.py) | Builds `submissions/submission.json` and `.zip` from the production models |
| [`make_final_candidate.py`](make_final_candidate.py) | Builds and validates a submission package (rebuild check, official loader, comparison with earlier uploads) |
| [`make_validation_submissions.py`](make_validation_submissions.py) | Validation Phase files from train-only models, scored with the official `evaluate()` |
| [`evaluation_metric.py`](evaluation_metric.py) | The organisers' macro F1, imported unchanged |
| [`baseline.py`](baseline.py) | Reproduces the official RandomForest baseline |
| [`ceilings.py`](ceilings.py) | Upper bound on macro F1 when identical feature vectors must share one prediction (experiment 004) |
| [`flowcheck.py`](flowcheck.py) | Flow-level paired check for facebook/instagram-targeted Task 1 changes (pre-registered in 067) |

## Reusable components (`flowkit/`, since experiment 102)

Small composable parts with no experiment logic. Runners import them; a new pipeline is a spec string, not new code.

| File | Role |
|---|---|
| [`flowkit/__init__.py`](flowkit/__init__.py) | Package entry: `DecisionPipeline`, `from_spec` |
| [`flowkit/bases.py`](flowkit/bases.py) | Named base models (`softvote`, `softvote_unweighted`, `task2_production`) |
| [`flowkit/calibration.py`](flowkit/calibration.py) | Calibration on cross-validated probabilities (`none`, `sigmoid`, `isotonic`) |
| [`flowkit/counts.py`](flowkit/counts.py) | Count-constrained labelling (`quota_assign`, `share_counts`, `label_counts`) |
| [`flowkit/features.py`](flowkit/features.py) | Ratio, rate and coefficient-of-variation features for either task (`ratio_features`) |
| [`flowkit/lookup.py`](flowkit/lookup.py) | Exact-signature lookup: label distribution of identical openings, leave-one-out on training rows (`ExactLookup`) |
| [`flowkit/members.py`](flowkit/members.py) | Ensemble members by name (LightGBM, XGBoost, RF, ExtraTrees, kNN-Manhattan) and nested Optuna tuning (`tune`) |
| [`flowkit/pipeline.py`](flowkit/pipeline.py) | `DecisionPipeline` (base, calibration, counts) and spec strings such as `base=softvote,cal=sigmoid,counts=shares` |
| [`flowkit/postprocess.py`](flowkit/postprocess.py) | Prior correction (`prior_correct`) and Gaussian temporal smoothing within a batch (`temporal_smooth`) |
| [`flowkit/swap.py`](flowkit/swap.py) | Count-preserving consensus pair swap between two views (`consensus_pair_swap`) |
